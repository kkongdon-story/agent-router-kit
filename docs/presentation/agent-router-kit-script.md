# agent-router-kit 발표 대본

대상: 비개발자 자동화 입문자  
길이: 약 8분  
말투: 초등학생도 이해할 수 있게 짧고 쉽게 설명

## 01-title

오늘은 Slack을 AI 리모컨처럼 쓰는 방법을 보여드리겠습니다.

이름은 `agent-router-kit`입니다. Slack에 말을 쓰면, 내 컴퓨터에 있는 Claude Code와 Codex가 일을 합니다.

어렵게 생각하지 않아도 됩니다. Slack은 버튼을 누르는 곳이고, Router는 그 버튼을 보고 누구에게 일을 줄지 정하는 담당자입니다.

시연에서는 먼저 Slack에 `코덱스 안녕`이라고 보내 보겠습니다.

## 02-problem

AI 도구를 쓰다 보면 이런 문제가 생깁니다.

Claude Code는 여기 있고, Codex는 저기 있고, 파일은 폴더에 있고, 문자는 휴대폰에 있습니다.

그러면 사람은 계속 복사하고 붙여넣고, 어디에 뭘 시켰는지 기억해야 합니다.

이 도구의 목표는 간단합니다. 여러 입구를 하나의 흐름으로 모으고, 필요한 일은 local workspace라는 로컬 공책에 남기는 것입니다.

## 03-remote

Slack은 리모컨입니다.

TV 리모컨에서 전원 버튼, 음량 버튼이 따로 있듯이, 여기서는 호출명이 버튼입니다.

`코덱스`라고 시작하면 Codex에게 보냅니다. `클로드`라고 시작하면 Claude Code에게 보냅니다.

`둘 다`라고 쓰면 두 도우미에게 같은 일을 같이 시킵니다.

이제 Slack에서 `클로드 안녕`과 `둘 다 한 문장으로 인사해`를 보내 보겠습니다.

## 04-router

Router는 교통정리 담당입니다.

사용자가 쓴 문장을 보고, 이것이 질문인지, 업무인지, 토론인지, 자료 정리인지 나눕니다.

예를 들어 `둘이 토론해`는 Debate Mode로 갑니다. 하지만 `업무 할일 테스트 작업 추가`는 토론이 아니라 local workspace 작업으로 가야 합니다.

이 구분이 중요합니다. 구분이 없으면 이전 토론의 문맥에 끌려가서 엉뚱한 답을 할 수 있습니다.

## 05-two-helpers

Claude Code와 Codex는 일을 처리하는 두 도우미입니다.

Codex는 코드, 구조, 실행 가능성 확인에 강합니다. Claude Code는 긴 문맥, 설명, 글의 흐름을 다루는 데 강합니다.

그렇다고 이름을 꼭 그대로 써야 하는 것은 아닙니다.

공식 이름은 Claude Code와 Codex이고, `클로드`, `코덱스`는 한국어 호출명입니다. `덱스`, `클로` 같은 짧은 이름은 사용자가 정한 별칭 예시입니다.

별칭은 env 파일의 `CLAUDE_ALIASES`, `CODEX_ALIASES`에서 바꿀 수 있습니다.

## 06-notebook

local workspace는 공책입니다.

AI가 답만 하고 끝나면 나중에 찾기 어렵습니다. 그래서 입력과 결과를 폴더에 남깁니다.

`inputs`는 들어온 재료입니다. `processed`는 처리된 결과입니다. `ledger`는 원장입니다.

예를 들어 문자에서 문의가 들어오면 `inputs/sms`에 입력 기록이 생기고, 해야 할 일이라면 `processed/tasks`에 TASK가 생깁니다.

## 07-commands

처음에는 명령을 많이 외울 필요가 없습니다.

`코덱스 안녕`, `클로드 이 문장 고쳐줘`, `둘 다 이 아이디어 봐줘`, `업무 할일 테스트 작업 추가` 정도만 알아도 시작할 수 있습니다.

그리고 헷갈릴 때는 이렇게 물으면 됩니다.

`slack agent router app으로 뭐 할 수 있어?`

중요한 점은 이 질문에 generic Slack 기능이 아니라 agent-router-kit 기능으로 답해야 한다는 것입니다.

## 08-debate

Debate Mode는 두 도우미가 서로 토론하는 모드입니다.

그냥 `코덱스 의견`, `클로드 의견`을 나란히 보여주는 보고서가 아닙니다.

한쪽이 말하면 다른 쪽이 받아서 반박하고, 다시 수정하고, 마지막에 합의안을 냅니다.

시작은 `둘이 토론해`입니다. 이어가고 싶으면 `다음` 또는 `계속`이라고 쓰면 됩니다.

흐름을 지우고 싶으면 `리셋 토론`이라고 입력합니다.

## 09-other-inputs

SMS와 Kakao는 Slack 말고 다른 입구입니다.

SMS는 카드 사용, 입금, 출금, 문의, 인증, 알림 같은 문자를 구분할 수 있습니다.

Kakao는 사용자가 의도적으로 준비한 대화방 내용을 local workspace로 가져올 수 있습니다.

하지만 처음부터 켜지 않아도 됩니다. 먼저 Slack 라우터가 잘 되는지 확인하고, 필요할 때 하나씩 붙이는 것이 좋습니다.

## 10-install-with-ai

이 프로젝트의 중요한 포인트는 설치도 AI와 같이 한다는 점입니다.

사용자는 모든 명령어를 외울 필요가 없습니다. `INSTALL_WITH_AI.md`를 Claude Code나 Codex에게 보여주면 됩니다.

AI는 먼저 DryRun으로 안전하게 확인합니다. 그다음 설치 스크립트를 실행합니다.

단, 토큰은 절대 AI 채팅창에 붙여넣지 않습니다. 사용자가 직접 로컬 env 파일에 넣습니다.

## 11-safety

보안 규칙은 단순합니다.

첫째, 토큰은 AI 채팅창에 붙여넣지 않습니다.

둘째, 토큰은 GitHub에 올리지 않습니다.

셋째, 처음에는 비공개 테스트 채널에서만 씁니다.

넷째, SMS나 Kakao처럼 민감한 입력은 정말 필요할 때만 켭니다.

자동화는 편하지만, 내가 어디까지 연결했는지 알고 쓰는 것이 더 중요합니다.

## 12-next-step

첫 목표는 작은 성공입니다.

Slack에서 `코덱스 안녕`을 보냈고, 답이 왔다면 첫 번째 성공입니다.

`클로드 안녕`도 되고, `업무 할일 테스트 작업 추가`가 local workspace로 들어가면 기본 흐름은 완성입니다.

그다음에 SMS나 Kakao를 선택해서 붙이면 됩니다.

즉, 이 도구는 거대한 시스템을 한 번에 만드는 것이 아니라, Slack이라는 리모컨에서 시작해 내 로컬 공책으로 차근차근 쌓아 가는 방식입니다.
